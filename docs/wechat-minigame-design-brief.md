# 手机精致 FPS 微信小游戏项目设计文档

> 用途：作为新开微信小游戏/微信小程序项目的产品、玩法、系统和技术设计输入。
>
> 重要结论：实时 3D FPS 不建议做成普通“微信小程序页面项目”，应优先做成 **微信小游戏**。普通小程序适合页面、表单、商城、工具；本项目需要实时渲染、触控、音频、AI、战斗主循环，适合小游戏运行环境。

## 1. 项目定位

### 1.1 一句话目标

制作一款 **手机上操控很容易、画面精致好看、反馈爽快清晰的第一人称 5v5 单机 FPS 微信小游戏**。

### 1.2 品质参考

参考大型战术 FPS 的体验标准：

- 清晰读图：玩家能快速判断路线、掩体、敌我、交火方向。
- 顺手触控：移动、瞄准、开火、跳跃、装弹、切枪都能在手机上自然完成。
- 强反馈：开枪、命中、受伤、击杀、胜负、奖励都有明确音画反馈。
- 精致场景：不走低模方向，使用更多多边形、真实道具、材质、灯光和环境细节。
- 低学习成本：新玩家 30 秒内能理解目标并开始战斗。

只参考品质标准和交互体验，不复制任何商业游戏的地图、角色、商标、美术资产、音频或具体受版权保护内容。

### 1.3 微信小游戏版本策略

当前 Godot 版本目标是完整 5v5。微信小游戏新项目建议分两层：

| 层级 | 目标 | 说明 |
| --- | --- | --- |
| 完整目标 | 5v5 单机 FPS | 玩家 + 4 队友 AI 对战 5 敌方 AI，完整地图、成长、商业化。 |
| 首版 MVP | 1v1 / 2v2 / 3v3 轻量版 | 先验证微信小游戏性能、触控、启动包体和留存，再扩展到 5v5。 |

原因：微信小游戏是 WebGL/WASM/JS 环境，启动时间、包体、内存、CPU 和音频都比原生 Android 更敏感。首版应优先验证“能不能顺、能不能爽、能不能稳定”。

## 2. 产品支柱

1. **手机易操控**：默认触控布局必须可玩；按钮大小、透明度、灵敏度可调。
2. **清晰战术读图**：地图有主路、侧路、掩体组、地标，避免迷路。
3. **精致真实观感**：程序化真实风格，不以低模为目标。
4. **强即时反馈**：射击、命中、击杀、死亡、胜负、奖励反馈必须明显。
5. **性能稳定**：优先保证真机 30 FPS、低发热、低崩溃率。
6. **商业化不阻塞玩法**：激励广告、星星、解锁、去广告都不能阻止玩家完成核心战斗。

## 3. 核心游戏循环

```text
启动游戏
  -> 首页
    -> 每日奖励 / 每日任务 / 设置 / 教程
    -> 开始游戏
      -> 地图选择
        -> 免费地图直接进入
        -> 锁定地图用星星解锁，星星不足可看激励广告补足
      -> 战斗加载
        -> 5v5 / 轻量 MVP 对战
          -> 玩家战斗
          -> 玩家死亡后观战队友
          -> 一方全灭或时间到结算
      -> 结算页
        -> 显示胜负、击杀、奖励、任务进度
        -> 下一局 / 返回首页
```

## 4. 比赛规则

### 4.1 队伍

| 队伍 | 构成 |
| --- | --- |
| 蓝队 | 玩家 + 队友 AI |
| 橙队 | 敌方 AI |

完整目标为 `5v5`：蓝队 `玩家 + 4 AI`，橙队 `5 AI`。

微信小游戏 MVP 可先用：

- `1v1`：最快验证枪感、AI 和触控。
- `2v2`：验证队友、观战和小规模协作。
- `3v3`：接近完整体验但性能压力可控。

### 4.2 时间与胜负

- 单局时长：`300 秒`。
- 任意一方全灭：另一方立即获胜。
- 时间到：按存活人数判胜。
- 存活人数相同：平局。

```text
if orange_alive == 0: 蓝队胜利
else if blue_alive == 0: 橙队胜利
else if remaining_time <= 0:
  if blue_alive > orange_alive: 蓝队胜利
  else if orange_alive > blue_alive: 橙队胜利
  else: 平局
```

### 4.3 生命值

| 对象 | 生命/护盾 |
| --- | --- |
| 玩家 | `100 HP + 30 护盾` |
| AI | `100 HP` |

玩家死亡后不复活，进入观战模式。观战时隐藏开火、跳跃、装弹、切枪等不可用按钮。

## 5. 武器设计

### 5.1 武器列表

| 武器 | 类型 | 数值 | 定位 |
| --- | --- | --- | --- |
| M416 | 射线武器 | `18` 伤害，`0.11s` 冷却 | 主战武器，高射速，中距离稳定输出。 |
| 巴雷特 | 射线武器 | `105` 伤害，`1.45s` 冷却 | 高伤低速，远距离点杀，能一枪击杀普通 AI。 |
| RPG | 投射物 | `95` 伤害，`5.0` 爆炸半径，`2.6s` 装弹 | 高风险范围爆发，适合打掩体后敌人。 |

### 5.2 弹药逻辑

- 每把武器有弹匣和备弹。
- 弹匣耗尽后可手动/自动装弹。
- 地图存在弹药箱，拾取后补充各武器备弹。
- 弹药箱被拾取后约 `28 秒` 刷新。

### 5.3 命中与伤害

```text
射线武器伤害 = weapon.damage
RPG 爆炸伤害 = weapon.damage × clamp(1 - distance / splash_radius, 0.25, 1.0)
```

### 5.4 枪感目标

- 每把枪需要不同声音、后坐力、屏幕反馈、枪口火焰和命中反馈。
- 枪声根据距离衰减：近处响，远处弱。
- 后续可加入：受击方向、低弹药提示、爆炸距离衰减、遮挡音效。

## 6. 手机触控设计

### 6.1 默认布局

| 区域 | 功能 |
| --- | --- |
| 左下 | 浮动摇杆移动。 |
| 右半屏空白区域 | 滑动瞄准。 |
| 右下 | 主开火按钮。 |
| 左侧中部 | 备用开火按钮，方便移动中射击。 |
| 右下按钮组 | 跳跃、装弹、切枪。 |
| 顶部/侧边 HUD | 血量、护盾、子弹、倒计时、比分、观战信息。 |

### 6.2 操控原则

- 非按钮区域滑动只控制视角，不直接开火。
- 开火按钮支持按住持续射击。
- 移动摇杆和开火使用独立触点，保证移动中可持续射击。
- 切枪按钮需要去抖，避免一次点击触发多次。
- 观战和结算时隐藏无效按钮。
- 支持安全区、按钮缩放、透明度、灵敏度配置。

### 6.3 后续手感增强

微信小游戏新项目建议优先做：

1. 移动端灵敏度单独配置。
2. 开火按钮大小/透明度设置。
3. 轻量辅助瞄准：准星接近敌人时降低视角速度。
4. 训练场/靶场：用于测试默认手感。
5. 触控误触统计：记录首次游玩是否频繁误按。

## 7. AI 设计

### 7.1 AI 状态机

AI 至少包含：

| 状态 | 行为 |
| --- | --- |
| PATROL | 按作战路线巡逻。 |
| CHASE | 发现敌人后追击。 |
| ATTACK | 有视线且距离合适时攻击。 |
| SEEK_AMMO | 当前武器无弹时寻找弹药箱。 |
| DEAD | 死亡后停止行动和输入。 |

### 7.2 交战距离

| 武器 | AI 有效交战距离 |
| --- | --- |
| M416 | `45` |
| 巴雷特 | `85` |
| RPG | `50` |
| 未知武器 | `32` |

简单难度应更接近玩家后再开火，避免远距离原地打不中导致死局。

### 7.3 寻路方案

建议采用“两层导航”：

1. **全局路径**：地图级可走点图，使用 AStar/A* 查找从当前位置到目标的中间点。
2. **局部避障**：接近墙角、柱子、道具时使用 Context Steering 扇形采样，选择清障距离更好的方向。

AI 防卡墙规则：

- 不只在左右两边来回切换。
- 多方向采样并给候选方向打分。
- 避障方向短时间锁定，避免“左走两步、右走两步”。
- 检查是否真的靠近目标；如果移动但距离目标没有变近，进入脱困方向。
- 连续卡住时推进到下一个航点或回到路线。

### 7.4 微信小游戏性能注意

- AI 数量从 `1v1/2v2/3v3` 开始递增测试。
- A* 不要每帧重算，路径应缓存并定期刷新。
- 视线检测、射线检测、避障检测要限频。
- 复杂 AI 协同放到后期，先保证不卡墙、不发呆、不无脑秒杀。

| `factory` | 废弃工厂 | 灰色钢铁厂房，锈色钢架，仓库通道与铁箱掩体。 | 6 |
| `jungle` | 丛林营地 | 绿色丛林，巨型树桩柱，木屋营地，石堆掩体。 | 10 |
| `ruins` | 古城遗迹 | 棕色石砖古迹，双门神殿居中，残垣断壁散布全图。 | 10 |

| `space` | 太空站 | 深空站，白色金属核心模块，蓝绿发光走廊。 | 15 |
| `volcano` | 火山熔岩 | 橙红火山地貌，熔岩流贯穿全图，火山锥居中爆发。 | 18 |

微信小游戏 MVP 建议首发只做 `1-3` 张地图：

1. `city`：标准战术 FPS 基准地图。
2. `night_city`：视觉样板地图。
3. `factory` 或 `harbor`：工业/码头风格，利于掩体和战术动线。

### 8.2 每张地图必须具备

- 主路线：最直接、最容易交火。
- 侧路线：绕后或避开主火力。
- 掩体组：短掩体、中掩体、高掩体组合。
- 地标：玩家能用一句话报点，如“中路高楼”“码头仓库”。
- 补给点：弹药箱位置不能太偏，也不能完全暴露。
- AI 航点：用于巡逻、进攻、防守和全局寻路。
- 性能边界：控制实时灯、透明材质、粒子、动态节点数量。

## 9. 局外成长与奖励

### 9.1 星星系统

星星是本地软货币，用于解锁地图。

| 来源 | 奖励 |
| --- | --- |
| 胜利 | `+1` 星 |
| 玩家 MVP 胜利 | `+2` 星 |
| 每日奖励 | `+2` 星 |
| 今日击杀 3 人 | `+1` 星 |
| 今日赢得 1 局 | `+2` 星 |
| 今日战斗获得 2 星 | `+1` 星 |
| 激励广告补星 | 按地图缺口补足 |

### 9.2 地图解锁

```text
if map.cost == 0: 已解锁
else if map.id in purchased_maps: 已解锁
else if total_stars >= map.cost: 可消耗星星解锁
else: 可通过比赛、每日奖励、每日任务、激励广告获得星星
```

星星不足时，激励广告奖励不固定 `+3`，而是：

```text
reward_amount = max(1, map.cost - total_stars)
```

这样玩家能一次补足当前地图所需星星。

### 9.3 商业化边界

- 广告不可用时，不阻塞进入免费地图和核心战斗。
- 所有奖励统一走星星发放接口，避免 UI 直接改数据。
- 未接入真实广告前，不把调试奖励包装成真实广告收益。
- 接入前必须补齐隐私政策、用户协议、SDK 清单和数据安全说明。

## 10. UI/HUD 设计

### 10.1 首页

首页只保留关键入口：

- 标题与版本信息。
- 星星总数。
- 开始游戏。
- 教程。
- 设置。
- 每日奖励/每日任务入口。

手机屏幕上避免信息堆满。每日任务和每日奖励可收纳到弹层。

### 10.2 地图选择

地图卡片展示：

- 地图名。
- 简短描述。
- 解锁成本。
- 是否已解锁。
- 当前星星。
- 星星不足时显示“补足星星”。

### 10.3 战斗 HUD

必须显示：

- 血量/护盾。
- 当前武器。
- 弹匣/备弹。
- 倒计时。
- 蓝/橙存活人数。
- 准星。
- 命中反馈。
- 击杀提示。
- 观战提示。

### 10.4 结算页

显示：

- 胜利/失败/平局。
- 胜负原因。
- 玩家击杀数。
- 本局奖励星星。
- 每日任务进度。
- 下一局 / 返回首页。

## 11. 音频设计

### 11.1 音频目标

- 菜单：冷静电子氛围音乐。
- 战斗：更紧张的鼓点和低音。
- 枪声：M416 清脆短促，巴雷特重狙低频冲击，RPG 喷气和爆炸感。
- 距离：枪声按距离改变音量。
- 移动端稳定：避免过多同时播放，长音乐用平台友好方式循环。

### 11.2 微信小游戏注意

微信小游戏建议：

- 长音乐优先考虑平台音频接口或压缩音频资源。
- 限制同时音效数量。
- 高频音效做缓存复用。
- 真机测试 Android/iOS 音频延迟、丢音、循环稳定性。

## 13. 微信平台能力接入

### 13.1 必接

- 本地存储：保存星星、地图、设置、任务。
- 激励视频广告：补星、胜利翻倍、失败补偿。
- 分享：分享战绩或拉新。
- 震动：受伤、击杀、胜利等轻反馈。
- 错误日志/性能统计：记录启动失败、黑屏、卡顿、崩溃。

### 13.2 可选

- 云开发：保存排行榜、远程配置、活动配置。
- 开放数据域：好友排行榜。
- 订阅消息：召回，但不要过度打扰。
- CDN：地图资源、音频、纹理按需加载。

### 13.3 包体与启动策略

微信小游戏需要重点控制：

- 首包小：只放启动必需逻辑、首页、基础 UI、首张地图必要资源。
- 资源按需加载：地图、音频、贴图、模型分场景加载。
- 分包/CDN：重资源放 CDN 或分包，避免首包过大。
- 启动体验：封面图、进度条、加载文案要明确。
- 性能检测：真机记录启动耗时、首帧时间、FPS、内存、发热。

## 14. 微信小游戏 MVP 建议范围

### 14.1 第一阶段：可跑通版本

- 首页。
- 设置。
- 1 张地图：`city` 或 `night_city_lite`。
- 1 把武器：M416。
- 1v1 AI。
- 60-120 秒小局。
- 基础触控：摇杆、滑屏、开火、装弹。
- 基础胜负结算。
- 本地星星保存。

验收：微信开发者工具和真机都能启动、战斗、结算，不黑屏，不崩溃。

### 14.2 第二阶段：核心体验版本

- 3v3。
- 3 把武器。
- 3 张地图。
- 每日奖励。
- 地图解锁。
- 激励广告补星。
- 命中、击杀、受伤、胜负音画反馈。

验收：新玩家 1 分钟内能完成击杀；一局完整跑完不卡死。

### 14.3 第三阶段：上线候选

- 扩展到 5v5 或保持 3v3 但提升品质。
- 更多地图。
- 新手教程。
- 训练场。
- 分享、排行榜、广告、统计。
- 商店素材、隐私政策、用户协议、数据安全声明。

## 15. 性能预算建议

| 项目 | MVP 建议 |
| --- | --- |
| 目标帧率 | 中端机稳定 `30 FPS`。 |
| AI 数量 | 从 `1v1` 到 `3v3` 递增测试。 |
| 实时灯光 | 尽量少，优先烘焙/假光/贴图表现。 |
| 粒子 | 枪口火焰、命中火花短生命周期。 |
| 音效并发 | 限制最大通道数。 |
| 地图资源 | 首版只加载当前地图。 |
| 射线检测 | 限频、复用对象，避免每帧大量检测。 |
| A* 寻路 | 缓存路径，定期刷新，不每帧重算。 |

## 16. 验收清单

### 16.1 玩法验收

- [ ] 首页能进入地图选择。
- [ ] 免费地图能直接开局。
- [ ] 锁定地图能用星星解锁。
- [ ] 星星不足时能通过激励广告补足。
- [ ] 玩家能移动、瞄准、开火、装弹、切枪。
- [ ] AI 能巡逻、追击、攻击、死亡。
- [ ] 玩家死亡后进入观战。
- [ ] 一方全灭或时间到能正确结算。

### 16.2 手机手感验收

- [ ] 默认按钮不挡视野。
- [ ] 移动中可以持续开火。
- [ ] 右屏滑动瞄准顺手。
- [ ] 观战/结算隐藏无效按钮。
- [ ] 新玩家 30 秒内理解操作。

### 16.3 微信平台验收

- [ ] 微信开发者工具可运行。
- [ ] Android 微信真机可运行。
- [ ] iOS 微信真机可运行。
- [ ] 激励广告失败时有兜底提示。
- [ ] 本地存档稳定。
- [ ] 分享/广告/统计不影响战斗主循环。

### 16.4 性能验收

- [ ] 首次启动无黑屏或长时间无反馈。
- [ ] 一局完整战斗不崩溃。
- [ ] 中端机接近或稳定 `30 FPS`。
- [ ] 音频不爆音、不无限叠加。
- [ ] AI 不明显卡墙或来回抖动。

## 17. 不做事项

- 不复制任何商业 FPS 的地图、角色、技能、商标、音频、美术资产。
- 不在前端硬编码广告位 ID、支付密钥、服务端密钥。
- 不为了画质堆资源导致首包过大、启动过慢。
- 不让广告阻塞免费地图和核心战斗。
- 不在未完成合规前接入真实付费。

## 18. 给新项目的第一批任务

1. 确认项目类型：微信小游戏，而不是普通微信小程序。
2. 选技术栈：Godot Web 转小游戏、Three.js/Babylon.js、自研 WebGL 或其他小游戏引擎。
3. 做 `1v1 + M416 + 1 张地图` 技术验证。
4. 接入基础触控：摇杆、右屏视角、开火、装弹。
5. 接入本地存档：星星、设置、教程状态。
6. 做真机性能测试：Android/iOS 启动、FPS、音频、触控。
7. 再决定是否扩展到 `3v3`、多武器、多地图和商业化。
